# Standing review rules

- Cite current file:line locations and an observable consequence for every finding.
- Follow changed symbols through existing callers and consumers across files.
- Treat duplicated decisions, dead code and needless defenses as simplification opportunities.
- Identify exposed credentials and secrets in code or logs.
- Explain broken persistence and data contracts, including the affected consumer.
- Do not flag formatting or personal style preferences.
- Prefer deleting unnecessary behavior to adding speculative guards.
